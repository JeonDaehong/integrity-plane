# 0006. Parquet key extraction

- Status: Accepted
- Date: 2026-10-09

## Context

Phase 5 reads key columns (and NOT NULL columns) from the Parquet data files a commit adds and
removes (spec §14 step 5, §21 `extract`). It must read only the needed columns, map them to the
table schema by Iceberg field ID, accept the physical representations Iceberg writers produce, and
fail closed on anything it cannot map unambiguously.

## Decision

- **Library:** Apache arrow-rs `parquet` 60 with the `arrow` feature, plus `arrow-array` /
  `arrow-schema` 60 and `bytes` 1, in `integrity-iceberg` only (never in core).
  - License: Apache-2.0 (`arrow-array`: Apache-2.0 AND MIT); `bytes`: MIT.
  - Maintenance: Apache Arrow project, monthly releases. MSRV 1.88 (ours: 1.90).
  - Codecs enabled: `zstd` (Iceberg's default), `snap`, `lz4`, `flate2-rust_backend`; brotli and
    others are off.
  - **Native code:** `zstd` pulls `zstd-sys`, the C zstd library (BSD-3-Clause), compiled with the
    platform C compiler. Accepted because zstd is the default Iceberg codec and no pure-Rust zstd
    decoder is supported by `parquet`. All other enabled codecs are pure Rust.
- **API:** `extract_rows(Bytes, &[(FieldId, LogicalType)]) -> RowBatch`. Projection is by root column
  (`ProjectionMask::roots`), so only requested columns are decoded.
- **Column mapping by field ID only.** Every root column must carry a field ID; a file without them
  (e.g. a migrated table that relies on name mapping) is rejected, because treating its columns as
  absent would silently yield NULL keys, which MATCH SIMPLE and NULLS DISTINCT would then exempt.
  Duplicate field IDs are rejected.
- **Absent field ⇒ NULL.** A requested field ID that the file does not contain reads as NULL in every
  row (a column added after the file was written). Iceberg v3 `initial-default` is not applied;
  Phase 6 must reject commits to tables whose constrained columns have one.
- **Type acceptance is by key family** (RFC 0001): `int`/`long` data for an Integer column
  (`int → long` widening); decimals stored as INT32, INT64 or FIXED_LEN_BYTE_ARRAY with the table's
  scale (precision may differ); µs and ns timestamps, with the time zone presence matching the table
  type; UTF-8 strings; any binary encoding for binary; `fixed[16]` for UUID. Everything else, including
  a different decimal scale, is a type mismatch. Columns of non-key types are read only for NULL-ness.
- **Nested key fields are unsupported** in 0.1 (field inside a struct): `NestedField`. A top-level
  struct may still be a NOT NULL target.
- **License exception:** `tiny-keccak` (CC0-1.0, public domain) is reached only at compile time
  through a proc-macro (`arrow-select` → `ahash` → `const-random`); `deny.toml` allows it for that
  crate alone.
- **Errors** are all reported as `UNSUPPORTED_COMMIT_OPERATION`: the Plane cannot prove the commit.

## Consequences

- Tests read fixtures written by pyarrow (the Parquet C++ implementation, as used by PyIceberg),
  generated by a committed script, covering every key family, NULLs, several row groups, zstd,
  dictionary encoding, all three decimal encodings and widened `int` data. A property test round-trips
  random composite tuples through the arrow-rs writer.
- Files written by Java writers (Spark, Flink via parquet-mr) are exercised only in Phase 7
  compatibility tests.
- `extract_rows` takes the whole file in memory; streaming from object storage and the read budget
  (spec §17.1) come with the object-store integration in Phase 6.

## Alternatives considered

- *Reading by column name*: breaks on renames, which Iceberg allows freely.
- *iceberg-rust's reader*: brings the whole Iceberg runtime (async, object store) into extraction; the
  adapter will use iceberg-rust for metadata in Phase 6 if its ADR says so, but key extraction stays a
  small, synchronous, testable function.

## Amendment: ranged reads

Extraction no longer downloads whole files. It reads the file size, the footer (one tail read of
64 KiB, or exactly the footer if larger), then only the column chunks of the requested root columns,
from every row group, with ranged reads (`FileIo::read_range`; ranged GETs on object stores). The
Parquet reader runs over just those ranges and fails if it ever needs another byte. Deletion vector
blobs are read the same way, by their manifest offset and size. Storage errors and the validation
budget keep their own codes (`STORAGE_READ_FAILED`, `VALIDATION_BUDGET_EXCEEDED`). A 10 MB file
with 1 KB rows now costs 1.6 % of its size to validate.
